# odd-button — research comparison (v2)

- **Date / source revision:** 2026-11-18. Implementation tree `oddkin-a1-main` at `e84a08e3` before the v2 work, which already carries the v1 design (spinner centred over retained content; selected-loading paint). The v1 research and specification are archived verbatim in [the v2 run](../../runs/2026-11-18-button-redesign/v1-specification-archive.json).
- **Question:** the owner asked for the full Primitive Architect flow on `odd-button` without treating the current Figma button as authoritative. Beyond v1, how should icon-only actions, icon sizing, links that look like buttons and the Figma family structure work, without breaking 2,385 Figma instances, eleven transitive code consumers and the native CSS recipe?
- **Existing Oddkin sources / applicable ADRs:** `packages/components/src/button/*`, `styles/glyphs.ts`, the native recipe `button.native.styles.ts` (`@oddkin/components/css/button.css`), consumers in the registry; ADR0036, ADR0043, ADR0045 (vocabulary), ADR0041/0042 (palette), ADR0051 (ORCP, Proposed). v1 source IDs B-S1…B-S5 and B-I1…B-I3 are reused where they still apply; new IDs start at S06 / I04.
- **Research scope / exclusions:** icon-only geometry and naming, icon sizing, the loading presentation (refresh), link styling, toggle presentation, the Figma family structure. A destructive tone stays out of scope (ADR0045 records none). No external dependency is proposed.

## Contradictions and unresolved questions

- Icon size: Carbon and Primer keep 16 px beside text at every size; Spectrum and Fluent scale. Oddkin keeps 16 at sm and md and steps to 20 at lg, where the label is body-sized. A design judgement, revisable without an API change.
- Spectrum delays its spinner by a second; Oddkin leaves timing to the host.
- The native recipe's icon-only geometry needs `data-icon-only`; inference would need `:has()` and still could not see bare text nodes.
