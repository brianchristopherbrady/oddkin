## 2. Status vocabulary

| Status | Meaning |
| --- | --- |
| **Existing** | An Oddkin element implements the family today. |
| **Existing (variant)** | The family is a variant, size, or state of an existing element (an attribute value or slot usage). |
| **Planned (M10)** | Named in plan M10 (primitives, composites, collections, overlays, layout recipes). Not built. |
| **Planned (unlisted)** | Not named in M10 yet; the mapping proposes an element, recipe, or controller for the M10 catalog decision. Not built. |
| **Anatomy primitive** | A Figma building block shared by other families (for example `ListboxOption`); maps to a part or template piece of the planned element, not to its own element. |
| **Exploration** | Multiselect display and menu studies on page 356:62, with supporting primitives on page 158:22; recorded in the snapshot, not mapped until the owner says whether it is a contract (§7). |
| **Deferred (data grid)** | Deferred by the user (2026-10-21). No grid code or documentation this round. |

Layout spacing and minimums bind to the existing repository variables, including `layout.gap`,
`layout.inset`, `layout.item-min`, `layout.sidebar-width` and `layout.main-min`. Colors, borders,
radii and typography use existing component roles and text styles. No new global tokens or
breakpoints were introduced.

The final panel distinguishes a recipe-local container query from intrinsic wrapping: at 36rem
and 52rem, `defineLayoutRecipe()` can select 2 or 3 columns instead of the base 1 column. The
viewport remains constant in all comparisons. These local conditions do not replace
`navigation.expanded` (container `shell` at 48rem), or `page.medium` / `page.wide` (viewport media
conditions).

Figma documents query states and Split variants; it does not execute CSS queries or switch
variants on resize. AutoGrid uses wrapping minimum-width children for the six-item examples;
CSS also clamps below 256 px and retains empty tracks with `auto-fill`, so incomplete rows can
differ. Split's Figma state holds the preferred sidebar width while CSS grows side/main at
1:999. See `artifacts/figma-layout-2026-10-23/` for measured bounds and rendered evidence.

### 3.2 Picker · Listbox and Tree (2026-10-24)

The Composed components page has one `Oddkin/Common/Picker` family with 24 variants:

| Property | Values |
| --- | --- |
| Content | Tree, Listbox |
| Selection | Single, Multiple |
| State | Empty, Selected, Open, Focus, Invalid, Disabled |

Both content modes reuse the existing `multiselect/Field` family’s Picker value slot, the popover’s Picker
content/footer slots, existing chips and buttons. Tree adds two embedded variants using the shared navigation rows;
Listbox uses the existing ListboxSurface and ListboxOption sources. Multiple selection shows Roads, Rail and
Boundaries as three independent selections, with two chips and a `+1` count. Selecting or expanding a branch
does not cascade to descendants.

Single selection activates a value and closes. Multiple selection updates immediately; Done closes. Clear removes
the selection, and Escape dismisses without clearing it. The label and help stay outside the shared joined surface.
Focus surrounds the full open surface, with a separate focused row. The field is 40 px with 12 px inline padding;
the closed radius is 8 px. Focus geometry derives from focus width plus offset; indentation derives from navigation.indent.

Review frame `544:13991` is organized beneath Resizable panels. It includes both Tree selection modes, both flat
Listbox modes, labeled closed/focus/validation states, existing Tree loading/empty/error content adapted to fill the
popup, 320 px examples, and Dark variable-mode examples. Main variants are in `Definitions · Picker · Listbox & Tree`.

This began as a **Figma composition proposal**; the owner approved building it on 2026-10-25, and `odd-picker`

permits Listbox or Tree popups: the trigger keeps focus and names the active row with `aria-activedescendant`
(`aria-haspopup="tree"` with `items`), so odd-tree's roving focus does not apply inside the popup. Its rows,
expansion model, and APG hierarchy keys are odd-tree's (`src/collection/tree-model.ts`); the field, chips, clear
button, and popup wiring are odd-combobox's (`src/collection/option-field.ts`); the option rows are odd-listbox's.
The popup is a top-layer popover joined below the field, as wide, so it covers the help text that Figma lays out
below it. `design/figma/picker.json` records source IDs, per-variant field geometry, selected-row counts, review
cards and validation evidence. Slot-authored content is included in `components.json` and the reuse map.

Fixed (styling only, no API change): `odd-button` and the `button.css` path had the user agent's block padding
(1–2 px; Figma binds `space/none`) and no pressed fill for `secondary` and `ghost` (Figma `color/surface/sunken`);
`odd-input` had the user agent's block padding, the user agent's placeholder colour (Figma `color/text/secondary`),
no hover fill (Figma `color/surface/hover`; read-only and disabled fields keep theirs), and a primary label colour
when disabled (Figma `color/text/disabled`).

Deliberate differences:

- Figma's `Loading` state pads with `space/md` at every size; the code keeps each size's inline padding, so a button
  keeps its width when it starts loading (a Figma inconsistency).
- Figma insets the input's field frame by `space/2xs` to fit its focus ring; the shared focus ring is an outline,
  which takes no layout space.
- Figma insets the radio group's frame by `space/2xs` as well; the shared field takes no inset, so the legend lines up
  with the labels of the fields around it.
- A segment's inline padding (`control/padding/inline/sm`) is on its text, which sizes the segment; the segment's
  surface is its radio, drawn under the text.
- Figma draws focus rings as strokes with the card radius; the outline follows the control's radius plus the
  offset. The ring's colour and width are compared and equal.
- Placeholder line height is not compared: the placeholder renders in the control's line box, and engines report a
  user-agent value for the pseudo-element.
- Firefox applies no `:active` while Space is held, so pressed states are compared in Chromium and WebKit only.

default, unchanged here); Figma's card draws body text in `color/text/secondary` and a divider above the footer,
while the element lets slotted text inherit `color/text/primary` and has no divider; the element's `elevated` card
has no Figma variant. AI definitions on page 0:1 are not compared yet.
