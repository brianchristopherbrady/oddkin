## 2. Status vocabulary

| Status | Meaning |
| --- | --- |
| **Existing** | An Oddkin element implements the family today. |
| **Existing (variant)** | The family is a variant, size, or state of an existing element (an attribute value or slot usage). |
| **Planned (M10)** | Named in plan M10 (primitives, composites, collections, overlays, layout recipes). Not built. |
| **Planned (unlisted)** | Not named in M10 yet; the mapping proposes an element, recipe, or controller for the M10 catalog decision. Not built. |
| **Anatomy primitive** | A Figma building block shared by other families (for example `ListboxOption`); maps to a part or template piece of the planned element, not to its own element. |
| **Exploration** | Multiselect display and menu studies on page 356:62, with supporting primitives on page 158:22; recorded in the snapshot, not mapped until the owner says whether it is a contract (§7). |
| **Deferred (data grid)** | Deferred by the user (2026-10-21). No grid code or documentation this round. |

## 5. Icons

All icons live on page 359:2, "05 · Icons", under one library frame. Each appears once as an editable main
component in the General (949), GIS (156), or Healthcare (618) catalog. Duplicate source/preview grids have been
removed. All 162 earlier icon component IDs and their consumers remain; the 34 legacy Core UI definitions now
contain the original Oddkin artwork supplied in this repository.

The 1,723 SVG assets use a 20 px canvas, editable paths, 1.5 px physical strokes, rounded caps and joins,
and `color/text/primary` in Figma (`currentColor` in SVG). Shared interface, document, typography, object and
transport concepts belong in General; GIS contains mapping, geometry editing, spatial analysis, surveying,
terrain/raster and utility tools. Healthcare contains clinical care, records, medicines, anatomy and vitals.

The `gis-icons.json` and `healthcare-only-icons.json` inventories have 3,170 and 746 reference IDs respectively.
The healthcare expansion adds 570 assets and reuses 37 existing canonical icons, retaining blood groups,
test results, pack counts, gestational stages and source-qualified alternatives. Equivalent concepts share canonical artwork,
with all 3,916 IDs recorded in `design/icons/reference-map.json`. Filled and outlined references use Oddkin's
outline treatment; application references use original functional marks or letter badges rather than official
brand logos. Reference names and categories guide the artwork; no source SVG paths were copied. This is concept
coverage, not visual parity with the reference collections.

The artwork, SVG assets, Figma ID map, catalog, previews, generation and validation tools are in
[design/icons](../../design/icons/README.md), under the repository's MIT license. Built-in affordance glyphs
(chevrons, check, close, …) still come from the shared glyph module (§6). These SVGs remain optional author
content; the planned consuming icon package is separate work.

All three domains have generated `general-only-icons.json`, `gis-only-icons.json` and `healthcare-only-icons.json`
catalogs validated by the common `icon-catalog.schema.json`. They describe actual Oddkin artwork and include SVGs,
asset paths and stable Figma IDs. The supplied normalized reference catalogs are retained separately under
`design/icons/inventories/reference-catalogs/`, preserving all source identities and naming flags. Classification follows
artwork semantics, so common maps, layer controls, accessibility and science tools belong in General; qualified spatial
data belongs in GIS. The full audit moved 68 assets between galleries and checked all 1,723 canvases and 5,809 physical strokes.

## 7. Earlier Figma audit findings (2026-10-22)

The findings below record the earlier audit. Subsequent variable/style cleanup and page organization supersede
the old page locations, Shared theme references, raw overlay effects and radio/switch focus-radius findings.
The original icon artwork and replacement of the legacy Core UI vectors are documented in §5.

Observed in the snapshot (`design/figma/components.json`) and a read-only text-contrast check
(`design/figma/text-contrast.export.js`) on 2026-10-22.

1. **Unbound literals** (outside the icon set): raw drop shadows instead of the elevation effect style on the open
   surfaces of `select`, `combobox`, and `multiselect` (`0 1 2 #0000001f`, `0 4 12 #00000014`); disabled states drawn
   with layer opacity 0.5 (`checkbox`, `radio`, `switch`, `toggleButton`), 0.55 (`CommandItem`, `multiselect`), and
   0.65 (`multiselect/Field`) where other families use `color/text/disabled`; `number` stepper corners 7; `radio` and
   `switch` focus rings radius 10003 instead of `radius/full`; the `Splitter/horizontal` grip text in Roboto 12/16
   without a text style; `multiselect/Value/avatars` overlap spacing −4; icon stroke weight 1.5 on all 34 icons
   (no token).
2. **Inconsistent variants**: `button`, `button/sm`, `button/lg` are three sets whose `Size` property has one value
   each (one set with `Size=sm|md|lg` would match the code); most families put interaction states, data states, and
   specimens in one catch-all `State` property (for example `Tree`: Selected, Keyboard focus, Collapsed, Empty,
   Loading, Error); `radio` says `Selection=Selected` where `checkbox` says `Selection=Checked`; `badge` has no Info
   tone (ADR 0045 adds `info`); page 0:1 redraws `odd-button` and `odd-input` as 36 standalone components bound to a
   different variable collection than the Common `button` and `input`; `odd-model-select` on page 0:1 binds
   `border/default`, `repo/radius/md`, and `control/height/sm` where Common `select` binds `border/strong`,
   `control/radius`, and `control/height/md`; field focus rings use `card/radius` (input) and `card/radius` or
   `radius/lg` (select); `CheckboxOption` nests an interactive `checkbox` inside an option row.
3. **Contrast**: 1,914 text layers checked; 79 fall below 4.5:1, all in `color/text/disabled` (#767985). Outside the
   deferred data grid (13), 57 are disabled specimens and 8 are `Form` State=Submitting controls (3.76–4.34:1,
   exempt as inactive; `toggleButton` On + Disabled is 1.83:1), and one is a placeholder, `Form` State=Invalid
   "Enter a project name", at 4.34:1 on white. Non-text: the owner has changed light `color/border/strong` to
   #868997 in Figma (lowest 3.03:1, on sunken; Agent 2, 2fdf650); every family binds the variable, so components
   take the new value from the token.
4. **Exploration on the contract page**: the multiselect exploration (formerly page 256:62) now sits on page 158:22
   (12 sets, 2 components). Is it a contract now?
5. **Icon source and licence**: Figma records no source or licence for the 34 icons (§5). Of them, 21 are built-in
   affordance or tone glyphs (chevrons, check, minus, close, search, more, arrows, external, eye, lock, upload, file,
   user, plus, spinner, info, warning, checkCircle) that components draw themselves, so they would ship with
   `@oddkin/components` under its MIT licence. The other 13 are content icons: author content in specimens (bold,
   folder, grid, home, mail, settings), drawn by the native date and time inputs in code (calendar, clock), used only
   by the deferred data grid (sort), or unused (copy, download, filter, trash). Questions: (a) who
   drew them, or which set are they derived from, and under which licence? (b) Does Oddkin ship a content icon set at
   all? Proposal: ship only the built-in glyphs (one glyph module, once provenance is confirmed) and let `odd-icon`
   render author-supplied SVG, so consumers bring any icon set and pay for none they do not use.
6. **Families proposed not to build as their own elements** (each still lands, as a variant, part, or recipe):
   - variants of one element: `button/sm`, `button/lg`, `iconButton` (`odd-button` `size`, `label`); `search`,
     `number`, `dateTime` (`odd-input` `type`); `spinner` (`odd-progress` without a value, plus the shared spinner
     module); `alertDialog` and `drawer` (`odd-dialog` options on one dialog controller); `toggleButton` (a pressed
     state on `odd-button`, one button look); `Accordion` (`odd-disclosure` `name`, the native `<details name>`
     exclusive group);
   - parts of a composite (ARIA references stay in one tree): `radio`, `ListboxSurface`, `ListboxOption`, `MenuItem`,
     `CommandItem`, `CheckboxOption`, `NavigationItem`, `Splitter/*`;
   - CSS recipes or compositions (no behaviour, so no registration, shadow root, or upgrade per instance): `Form`,
     `List`, `Table`, `divider`, `keyboardKey`, and `typography` (type-role classes instead of `odd-text` and
     `odd-heading` elements, since native `h1`–`h6` and `p` already carry the semantics; a visually-hidden utility in
     the same recipe);
   - not built: the multiselect exploration (item 4), the data grid (deferred), icon assets (item 5).

Fixed (styling only, no API change): `odd-button` and the `button.css` path had the user agent's block padding
(1–2 px; Figma binds `space/none`) and no pressed fill for `secondary` and `ghost` (Figma `color/surface/sunken`);
`odd-input` had the user agent's block padding, the user agent's placeholder colour (Figma `color/text/secondary`),
no hover fill (Figma `color/surface/hover`; read-only and disabled fields keep theirs), and a primary label colour
when disabled (Figma `color/text/disabled`).

Deliberate differences:

- Figma's `Loading` state pads with `space/md` at every size; the code keeps each size's inline padding, so a button
  keeps its width when it starts loading (a Figma inconsistency).
- Figma insets the input's field frame by `space/2xs` to fit its focus ring; the shared focus ring is an outline,
  which takes no layout space.
- Figma draws focus rings as strokes with the card radius; the outline follows the control's radius plus the
  offset. The ring's colour and width are compared and equal.
- Placeholder line height is not compared: the placeholder renders in the control's line box, and engines report a
  user-agent value for the pseudo-element.
- Firefox applies no `:active` while Space is held, so pressed states are compared in Chromium and WebKit only.

Open, for the owner: Figma's `button` defaults to `Appearance=primary`, the element to `secondary` (an API
default, unchanged here); Figma's card draws body text in `color/text/secondary` and a divider above the footer,
while the element lets slotted text inherit `color/text/primary` and has no divider; the element's `elevated` card
has no Figma variant. AI definitions on page 0:1 are not compared yet.
