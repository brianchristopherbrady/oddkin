# Oddkin 1.0.0-beta.1 release notes

What changed for people who install Oddkin since 1.0.0-beta.0 (published 2026-10-28), drawn from [progress-log.md](../progress-log.md). Betas promise no stability; the contract freeze starts at 1.0.0 ([release-process.md](../release-process.md) §1).

```sh
npm install @oddkin/components@beta
```

## Changed

- **One copy of `@oddkin/core` per install.** `@oddkin/core` is now a peer dependency of `@oddkin/components`, `@oddkin/state`, `@oddkin/app`, and `@oddkin/ai`. `@oddkin/state` is a peer of `@oddkin/app`, and `@oddkin/components` a peer of `@oddkin/ai`. npm 7 and later and pnpm install peers themselves, so the install line above works as before. With Yarn, add the peers (`yarn add @oddkin/components @oddkin/core`). A version that does not fit a range now stops the install instead of nesting a second copy of core.
- **`latest` follows the betas.** Until a package has a stable version, each beta also moves the `latest` tag, so an install without a tag gets the newest beta.
- **Navigation rows.** In `odd-side-nav`, `odd-tree`, and `odd-picker`, the current or selected row's marker is a straight bar instead of a border bent by the row's corners (forced colours keep it). `odd-side-nav` reports the sidebar width as its intrinsic inline size.
- **Layout recipes inside eight components.** `odd-breadcrumbs`, `odd-calendar`, `odd-dialog`, `odd-disclosure`, `odd-file-input`, `odd-pagination`, `odd-toolbar`, and `odd-validation-summary` arrange their parts with Oddkin's layout recipes. Their APIs do not change.
- **Agent kits** in `@oddkin/components` and `@oddkin/ai`: `GUIDE.md` no longer lists the Oddkin repository's own commands, and `kit.json`'s fingerprint covers the files the package publishes, so a kit regenerated from the installed package is identical. The guide now names the theme's stylesheet and how to load the packages with an import map and no bundler, and the composition reference says a document sets only what an element's schema lists.

## Added

- **`@oddkin/core`:** development builds warn once, with both versions, when a second copy of core runs on the page (`[core.copies]`). Production builds are unchanged.
- **`@oddkin/components/css/layout.css`:** `.odd-grid-stretch` on `.odd-grid` or `.odd-auto-grid` gives each item's child its row's height, for cards of equal height.
- **`@oddkin/analyzer`:**
  - `oddkin-kit` writes and checks an agent kit for your own library: `oddkin-kit`, `oddkin-kit package [--check]`, and `oddkin-kit agents-md [--write | --check]`. `oddkin-kit llms --base <url> --out <dir>` writes an `llms.txt` index of the packages' kits for a documentation site. The generator is the `@oddkin/analyzer/kit` entry.
  - The metadata records each example's values (`definition`) when the source spells them out, so a published library's examples work as Workbench presets without its sources.
- **`@oddkin/workbench`:**
  - the component catalog's search, counts, category buttons, and cards with an optional live preview;
  - CSS custom properties in the interactive example's controls, in its generated code, and in share links;
  - `layout = 'reference'` for `<oddkin-component-panel>`, with section links, one scrolling controls region, and example cards (`examplePreview`);
  - `embedFiles()` in `@oddkin/workbench/node`, and "Embedding the panels" in its README for sites that embed the panels;
  - live previews in the catalog's cards, loaded as the cards come into view, with at most twelve kept;
  - Theme Studio's Export, which downloads the draft's configuration and the CSS generated from it;
  - `sections` on `<oddkin-component-panel>`, the sections to show, for a host's own tabs;
  - previews for a library described only by a standard Custom Elements Manifest: the element registers through the module whose exports hold its definition;
  - `oddkin workbench dev` keeps watching through renames, deletions, and reinstalls of the packages it watches, and a library without foundations opens on its components.
- **Examples:** `examples/ai-stream`, a chat page that streams answers over HTTP from its own server in the AI SDK UI message stream format, under a strict Content Security Policy.

## Fixed

- **`odd-input`:** date and time fields show their focus ring in WebKit (Safari), which focuses the field's segments and never matched `:focus-visible`.
- **`odd-checkbox`:** the check and minus marks are centred in their box.
- **`odd-combobox`:** the search glyph shows; it was painted under the field's box.
- **`odd-segmented-control`:** an option's text no longer breaks inside a word. The options sit in equal columns, each at least as wide as its option's longest word, and a control sized to its content gives every column room for the widest option.
- **`odd-tabs`:** vertical tab labels no longer break inside a word in a narrow box; the list takes up to 40% of the width, or more when a word needs it.
- **`odd-select`:** the chosen option's text sits in the middle of the field in Chromium.
- **`@oddkin/ai`:** with wide fonts, `odd-inline-assist`'s language select, `odd-artifact`'s revision select, and `odd-context-picker`'s URL field stay inside their rows.
- **`@oddkin/ai`:** a confirmed stop settles the message even when the stop endpoint answers before the stream's abort (`ConversationController.stop()`), and `odd-prompt-input` hides its "Sending…" line while Stop shows, so the Stop button stays in place.
- **`@oddkin/workbench`:** the interactive example applies every edit in order, also while its preview is still loading, and text fields update the preview as you type. A catalog card that a filter hides and shows again no longer shows an empty preview.

## Documentation

- A [support policy](../support.md): the browsers, Node, TypeScript, frameworks, package managers, and bundlers each release is tested with, and what is not tested.
- [SECURITY.md](../../SECURITY.md): report vulnerabilities privately through GitHub.
- The READMEs list the packages in the decided order and say what the accessibility testing covers; the components package's npm description no longer says "Accessible".

## Upgrading

- **npm:** no change is needed. The change-impact report against 1.0.0-beta.0 finds 347 changes, none incompatible: the examples gained their values in the metadata (317), and 29 stylesheets and one template (`odd-prompt-input`) changed.
- **Yarn:** add the peers (`yarn add @oddkin/components @oddkin/core`).
- **A pinned `@oddkin/core`** outside the other packages' ranges now stops the install instead of adding a second copy: install matching versions.
- **Development builds** warn with `[core.copies]` when a second copy of core runs on the page.

## Known issues and limitations

From the [support policy](../support.md):

- Safari is tested through Playwright's WebKit, not on Apple hardware, and mobile browsers are not tested.
- Screen readers are not yet verified.
- pnpm, Yarn, webpack, Rspack, and Node.js below 24 are not tested, and server-side rendering is not supported.
- `@oddkin/workbench` and `@oddkin/analyzer` keep their contracts open after 1.0.0 (ADR 0047).

## Checked for this release

Each of these runs in Chromium, Firefox, and WebKit:

- New projects install the packed packages and build with their own tools: Vite with TypeScript and Sass, React, Vue, Svelte, and the Angular CLI (Angular 22.2.3, on TypeScript 6.0).
- The golden path, from the packed packages: a library of two elements on `@oddkin/core`, themed with `oddkin-tokens`, described by `oddkin-analyze`, and documented with `oddkin workbench build`. An app then uses it with the router, state, and an AI element.
- Two copies of core at different versions on one page (the published 1.0.0-beta.0 beside this release), and elements moved into a same-origin frame (core-contracts.md §5.1).
- The AI demos and the streaming chat example, built from the packed packages.
- The release commit's CI run: lint, types, the build, the node tests, the browser tests, the metadata, the size budgets, the e2e tests, and the published packages. Its release evidence is attached to the GitHub Release.
