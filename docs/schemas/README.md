## Examples and validation

[examples/](./examples/) holds instances named `<schema>.valid.json` (must pass) and `<schema>.invalid-<reason>.json` (must fail). The invalid cases encode decisions:

- `oddkin-metadata.invalid-builddate.json`: an `updated` date with `observed` provenance is rejected (dates come only from authored metadata or source history; ADR 0027).
- `page-registry.invalid-theme-studio-card.json`: Theme Studio as a card is rejected (workbench-pages.md §4).
- `workbench-config.invalid-playground.json`: a `playground` destination is rejected (no separate Playground).
- `share-payload.invalid-width.json`: preview widths below 160px are rejected.
- `diagnostic.invalid-severity.json`: severities are `error`, `warning`, `info`, and a fix needs at least one edit.
- `project-context.invalid-path-and-hash.json`: capability paths are a closed set, and fingerprints are SHA-256.
- `agent-kit.invalid-budget-and-provenance.json`: the entry guide has a size budget, and entry provenance is `extracted`, `authored`, or `verified`.

Validated by `tests/schemas/schemas.test.ts` in `npm test` (Ajv 8 `Ajv2020`, `strict: true`, `allowUnionTypes: true`, plus `ajv-formats` 3; development dependencies only). On 2026-10-17 all 8 schemas compiled and all 12 examples gave the expected result. The schemas stay here until their owning packages exist (`@oddkin/analyzer` in M3, `@oddkin/workbench` in M3/M5); the test moves with them.
